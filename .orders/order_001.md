# order_001：画像圧縮・DeepJSCC研究系譜マップの開発

## 目的

以下のGitHubリポジトリを参考に，ニューラル画像圧縮・デジタルJSCC・通信路誤り耐性研究の論文関係を可視化するWebサイトを開発してください．

参考リポジトリ：
https://github.com/yryo1005/optimizer_map

完成したサイトはGitHub Pagesで公開できるようにしてください．

## 参考リポジトリの調査

最初にoptimizer_mapを調査してください．

特に以下を確認してください．

- D3.jsによるノード・エッジの描画
- 発表年と研究分野に基づくレイアウト
- ノードの選択・詳細表示
- 分野別フィルタ
- 複数手法の比較
- 系譜の経路表示
- 年スライダー
- JSONによる手法データの管理
- データ検証とGitHub Pagesへのデプロイ

参考リポジトリのUI・設計思想を踏襲しつつ，今回の研究分野に合わせて設計してください．

コピーを目的とせず，コードのライセンスと再利用条件を確認してください．

## 対象領域

1. 従来型画像圧縮
   - JPEG，JPEG 2000，BPGなど

2. 学習型画像圧縮（LIC）
   - CAE
   - Ballé 2017
   - Scale Hyperprior
   - Minnen 2018
   - Cheng 2020など

3. 生成・拡散型画像圧縮
   - DDCM
   - Turbo-DDCM
   - Robust Turbo-DDCMなど

4. 情報源・通信路分離符号化（SSCC）
   - JPEG＋LDPC
   - LIC＋LDPCなど

5. アナログ型DeepJSCC
   - Bourtsoulatze et al. 2019
   - その派生研究

6. デジタル型DeepJSCC
   - NECST
   - JCM
   - D²-JSCC
   - BlindSC
   - BFR-CAEなど

7. 通信路符号化・関連技術
   - LDPC
   - Polar Code
   - Turbo Codeなど

対象論文は，提供するDeep Researchの調査結果を出発点とし，必要に応じて一次論文を確認して追加してください．

## グラフの設計

ノードは，原則として論文・手法を表してください．

研究分野はタグ・背景領域・フィルタで表現してください．分類概念と個別論文を無条件に同じ種類のノードとして扱わないでください．

エッジには以下の種類を設けてください．

- 技術的改良・発展（derived_from）
- 技術・モデルの利用（builds_on）
- 共通研究課題（related）
- 比較対象（compared_with）

直接の派生関係が確認できない場合は，派生関係として接続しないでください．

論文間に関連があっても，先後関係だけを根拠に系譜エッジを作らないでください．

また，複数分野に属する研究を適切に表現してください．

## ノードのデータ構造

論文ごとにJSONファイルを管理してください．

最低限，以下の情報を持たせてください．

- ID
- 論文タイトル
- 著者
- 発表年
- 掲載先
- 原論文URL
- arXiv URLまたはDOI
- 研究分野（複数可）
- 情報源表現・潜在表現
- 通信路モデル（BSC，AWGNなど）
- アナログ／デジタルの区分
- 主要な技術的貢献
- 学習方法
- 評価指標
- 長所
- 制約・弱点
- 関連論文と関係の種類

未確認情報は推測で埋めず，未確認として扱ってください．

## 学術的な注意点

- JPEGは画像圧縮方式であり，LDPCは通信路符号である
- JPEG＋LDPCは，分離設計した場合のSSCCの具体例である
- LICとDeepJSCCは排他的な分類ではない
- アナログ型とデジタル型DeepJSCCを区別する
- 生成・拡散型画像圧縮を無条件にDeepJSCCの配下に置かない
- Robust Turbo-DDCMとBFR-CAEは，ビット誤り耐性という共通課題を持つが，必ずしも直接の派生関係ではない
- BFR-CAEは，BSCを含めた共同学習を行うという条件の下でデジタル型DeepJSCCに位置付ける

## 技術的な要件

参考リポジトリの構成を参考に，D3.jsを中心とした静的Webサイトとして実装してください．

論文情報と表示処理を分離し，論文追加時にJavaScriptの描画コードを変更しなくて済む設計にしてください．

以下の検証を設けてください．

- JSONスキーマの検証
- 重複IDの検出
- 不正な参照先の検出
- エッジ種別の検証
- 系譜関係の循環検出
- GitHub Pagesでの表示確認

## AIエディタによる解釈（作業開始時に追記）

- **タスクの種類**：静的Webサイトの開発（D3.js），論文データの整備（書誌情報の取得を含む文献調査），データ検証・テスト・CI の整備，README・document.md・report の作成である．`documentation.md`，`environment_construction.md`，ai-survey-kit の規約を適用する．
- **参考リポジトリ**：`yryo1005/optimizer_map` には LICENSE ファイルが存在せず，再利用条件が明示されていない．そのため，コードは複製せず，設計（年×分野の配置，分野範囲の囲み，詳細パネル，比較・経路・年スライダー，ノードごとのJSON，Pythonによる検証，Pages へのデプロイ）のみを参考に新規実装する．
- **Deep Research の調査結果**：プロジェクト内に該当するファイルが見つからなかった．代わりに order に列挙された論文・手法を起点とし，書誌情報は ai-survey-kit の `surveykit.py`（OpenAlex，arXiv，Crossref）で API から取得した値のみを用いる．記憶から書誌情報を補わない．
- **論文の内容**：ノードの技術的な項目（貢献，通信路モデル，学習方法など）は，API から取得した要旨と，ローカルに存在する論文PDF・研究プロジェクトの文書から確認できた範囲のみを記入し，確認できない項目は `null`（表示上は「未確認」）とする．各エッジには根拠の種類（要旨，本文，プロジェクト文書など）を記録する．
- **論文でないノード**：BPG（Webで公開された実装），JPEG＋LDPC・LIC＋LDPC（分離設計の構成例），BFR-CAE（未公開の研究コード `../autoencoder/`）は，`kind` で論文と区別し，書誌情報が無いことを明示する．
- **リポジトリ名**：`image-compression-map` を想定し，GitHub Pages のパスに依存しない相対パスで実装する．GitHub リポジトリの作成・push は実施せず，ユーザーの確認を待つ（ローカルの git commit も行わない）．
- **実行環境**：Node.js が無いため，ビルド・検証は Python（標準ライブラリ＋`jsonschema`），表示テストは Python 版 Playwright（Chromium）で行う．仮想環境は `.venv_tools`（`requirements_tools.txt`）とする．D3.js はサイト内に同梱（ISC License）し，CDN に依存しない．
- **将来的な拡張**（Semantic Scholar の引用数，arXiv の候補収集，年次トレンド，課題による検索）は今回は実装せず，データ構造で拡張可能にしておく．
