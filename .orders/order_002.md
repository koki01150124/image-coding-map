# order_002：研究系譜の正確性改善とプロジェクト名の変更

## 目的

`report_001`で実装した研究系譜マップについて，論文データの正確性と関係表示の妥当性を改善する．

併せて，プロジェクト名を`image-compression-map`から`image-coding-map`へ統一する．

既存の機能とデザインは原則として維持し，今回の変更によって動作を退行させないこと．

## 1．プロジェクト名の変更

以下の名称変更を行う．

| 項目 | 変更前 | 変更後 |
|---|---|---|
| プロジェクト名 | Image Compression Map | Image Coding Map |
| リポジトリ名 | `image-compression-map` | `image-coding-map` |
| GitHub Pagesのサブパス | `/image-compression-map/` | `/image-coding-map/` |

README，Webサイトのタイトル，HTMLメタデータ，GitHub Actions，テスト，ビルド設定，内部リンクなどを確認し，旧名称への依存を解消する．

コード内の旧名称は検索して変更するが，変更履歴や引用など，過去の名称を保持する必要がある箇所は無理に書き換えない．

ローカルのプロジェクトディレクトリも必要に応じて変更する．ただし，作業中のディレクトリ移動によって環境やGit設定を破損させないこと．

GitHub上のリポジトリ作成・改名・pushは今回実施しない．

## 2．論文データの正確性の検証

`report_001`で未確認とされた論文情報を優先的に検証する．

### 対象

- 要旨のみで確認した9件
- D²-JSCCの未確認項目
- ADJSCCの技術的な参照元
- 書誌情報の取得時に不整合が確認された文献
- その他，ノードの内容と一次資料の間に不整合がある項目

### 検証項目

- 論文タイトル
- 著者
- 初出年と正式な掲載年
- 掲載先
- 通信路モデル
- 情報源表現
- 学習方式
- 主要な貢献
- 評価指標
- 技術的な制約・弱点

可能な限り原論文の本文を参照し，根拠を確認する．

本文で確認できない内容は推測で補完せず，未確認として記録する．

既存のデータスキーマと検証手順を維持し，必要最小限の変更で対応する．

## 3．発表年の扱いの改善

現在は初出年，正式掲載年，研究開発年が混在する可能性があるため，区別できるようにする．

### 要件

- 年代軸の基準を明確に定義する
- 原則として論文の最初の公開年を年代軸に使用する
- 学会・論文誌への正式掲載年が異なる場合は詳細パネルに併記する
- プレプリントと正式掲載版を重複した別論文として扱わない
- 標準規格・ソフトウェア・構成例には適切な年の意味を定義する
- BFR-CAEのような未公開研究では，研究開発年を論文発表年として表示しない

NECSTなど，プレプリント公開年と正式掲載年が異なる論文について表示を確認する．

年スライダーの動作とデータの整合性を維持すること．

## 4．系譜経路と関連経路の分離

現在の経路表示では，技術的な継承関係と比較・関連関係が同じ経路探索に含まれる場合がある．

これらを明確に分離する．

### 技術的系譜

以下の関係のみを対象とする．

- `derived_from`
- `builds_on`

論文間で技術がどのように発展したかを確認するために使用する．

方向性を持つ関係については，派生元と派生先を区別する．

### 関連経路

以下を含むすべての関係を対象とする．

- `derived_from`
- `builds_on`
- `related`
- `compared_with`

技術的継承とは限らない関連性の探索に使用する．

関連経路には比較対象や共通研究課題が含まれることを明示する．

### UI

- 「技術的系譜」と「関連経路」を切り替えられるようにする
- 初期状態は「技術的系譜」とする
- 技術的系譜が存在しない場合は，存在しないことを明示する
- 比較対象や共通研究課題の関係を，直接的な改良・発展として表現しない
- 関係の種類によって線種または色を区別する
- ノード選択時の直接関係の強調機能は維持する

特に，BlindSCとDeepJSCC（Bourtsoulatze）を例として動作を検証する．

## 5．研究分野の分類の再確認

各ノードの所属分野を確認し，学術的に不適切な分類がないか検証する．

特に以下に注意する．

- LICとDeepJSCCは排他的な分類ではない
- DDCM，Turbo-DDCM，Robust Turbo-DDCMを無条件にDeepJSCCへ分類しない
- JPEGは画像圧縮方式，LDPCは通信路符号である
- JPEG＋LDPCなどの構成例と，個別の論文を区別する
- Shannonの情報理論に関する基礎研究を，特定のSSCC実装方式と混同しない
- BFR-CAEは未公開研究として扱い，その分類根拠を明記する

分類の変更が必要な場合は，根拠を`report_002.md`に記録する．

## 6．表示の改善

既存のD3.jsによる可視化を維持したまま，以下を改善する．

- 初期表示では重要な技術的発展関係を優先して表示する
- 比較対象・共通研究課題のエッジによる視覚的混雑を抑える
- 2015年以降など，特定期間に注目できる表示方法を用意する
- ノードやラベルの重なりを防止する
- ライト・ダークモードの両方で視認性を確認する

大規模なUIの再設計は行わず，既存の操作体系を尊重すること．

## 7．検証

既存テストに加えて，以下を確認する．

1. 旧名称に依存するURLや設定が残っていない
2. `/image-coding-map/`で正常に表示できる
3. 論文の初出年と正式掲載年を適切に区別できる
4. 技術的系譜に`related`や`compared_with`が混入しない
5. 関連経路では4種類の関係を探索できる
6. 不正な分類や参照関係を既存の検証で検出できる
7. 検索・比較・年スライダー・詳細パネルが引き続き動作する
8. ライト・ダークモードで表示が破綻しない
9. SVG・PNGの書き出しが正常に動作する

ブラウザテストを実施し，可能であれば主要画面のスクリーンショットを保存する．

- **タスクの種類**：既存サイトの改修（開発），論文の書誌・内容の検証（文献調査），テスト・文書の更新である．`documentation.md`，`environment_construction.md`，ai-survey-kit の規約を引き続き適用する．
- **名称変更**：コード・設定・README・document.md・テストの旧名称を `Image Coding Map`／`image-coding-map` に変更する．`.orders/` と `.reports/report_001.md` は作業の履歴であるため書き換えない．ローカルのディレクトリは既に `image-coding-map` であり移動しない．
- **年の扱い**：年代軸の `year` を「最初の公開年」と定義する．論文は arXiv ID（YYMM）が示す初版の年と正式掲載年のうち早い方，標準規格は解説論文の最初の公開年，ソフトウェアは最初の公開版の年，構成例は収録論文で最初に比較対象として用いられた論文の初出年とする．正式掲載（掲載先と年）は新しいキーに記録し，詳細パネルに併記する．正式掲載の情報は library.json（OpenAlex），DBLP・Crossref の API，論文の本文の記載から確認できたもののみ記録し，確認できない場合は未確認とする．
- **未公開研究**：BFR-CAE は発表年を「未公開」と表示し，年代軸上の位置は研究開発年による配置であることを明示する（年スライダーの判定には配置の年を用いる）．
- **重複の防止**：同じ arXiv ID・DOI・タイトルを持つノードを検証でエラーとする．
- **経路**：比較画面に「技術的系譜／関連経路」の切り替えを設け，初期状態を技術的系譜とする．技術的系譜は `derived_from` と `builds_on` のみを有向にたどり（直系，または共通の派生元を持つ場合），存在しなければその旨を表示する．関連経路は4種類を向きを無視してたどり，各段の関係の種類を表示する．マップ上の強調色も両者で分ける．
- **分類の再確認**：Shannon 1948 を SSCC の分野から外し，構成例から Shannon 1948 への `builds_on` を見直す（構成例の根拠となった本文は Shannon 1948 を部品として用いていないため）．その他の変更は根拠とともに report_002 に記録する．
- **表示**：初期表示では `related` と `compared_with` を非表示とし（凡例のボタンで表示できる），表示期間（全期間／2015年以降 等）の選択を追加する．ノード・ラベルの重なりはブラウザテストで検査する．
- **実施しないこと**：論文の大規模な追加，自動収集，GitHub の操作，commit．
