# order_007：研究分野樹形図の設計と実装

## 目的

`image-coding-map`に，画像圧縮・画像伝送技術の研究分野を階層的に可視化する「研究分野樹形図」を追加する．

既存の研究系譜図が論文・手法間の技術的発展関係を示すのに対し，樹形図では研究分野の分類と各分野に属する論文・手法を示す．

分類設計から実装・検証まで一貫して実施すること．

## 1．既存プロジェクトの調査

最初に既存のソースコード，データ構造，研究分野の分類，UI構成を確認する．

特に以下を調査する．

- 既存の研究系譜図の実装
- 研究分野を管理するデータ構造
- 論文ノードの複数分野への所属
- 論文検索・詳細パネル・フィルタとの連携
- パターン表との表示切り替え
- GitHub Pagesのパス設定

既存の機能とデザインを原則として維持すること．

## 2．樹形図の分類設計

次の3領域を基本として，既存の論文データと一次資料を参照しながら階層構造を設計する．

1. 画像圧縮（Image Compression）
2. 通信路符号化（Channel Coding）
3. 画像伝送・情報源通信路符号化（Image Transmission / Source-Channel Coding）

下位分類の具体的な名称・階層数は，既存データに基づいて決定すること．

検討対象には，従来型画像圧縮，LIC，生成・拡散型画像圧縮，SSCC，JSCC，アナログ型・デジタル型DeepJSCCを含める．

### 分類上の注意

- JPEGは画像圧縮方式，LDPCは通信路符号である．
- JPEG＋LDPCは分離型画像伝送システムの構成例である．
- LICとDeepJSCCは排他的な分類ではない．
- 生成・拡散モデル型圧縮は，学習型圧縮と重複する場合がある．
- 生成モデルを使用したDeepJSCCも存在する．
- DDCM，Turbo-DDCM，Robust Turbo-DDCMを無条件にDeepJSCCの配下へ置かない．
- BFR-CAEは，BSCを考慮した共同最適化という前提でデジタル型DeepJSCCに位置付ける．
- 「研究分野への所属」と「技術的な派生・継承」を混同しない．

純粋な樹形図では表現できない分野の重複は，複数所属や関連表示によって補完すること．

## 3．データ構造

研究分野の階層構造を，論文ノードとは独立したデータとして定義する．

各分類には，原則として以下を持たせる．

- ID
- 日本語名
- 英語名
- 説明
- 親分類
- 子分類
- 分類基準
- 表示順序

分類体系の管理にはJSONなどの編集可能な形式を使用する．

既存の論文ノードを参照し，樹形図専用に論文情報を重複して管理しないこと．

複数分野に属する論文は，適切な複数の分類から参照できるようにする．

分類間の親子関係は循環を許さない構造とする．

## 4．樹形図のUI

既存サイトに「研究分野樹形図」の表示モードを追加する．

### 必須機能

- 研究分野を階層構造で表示
- 分類ノードの展開・折りたたみ
- ドラッグによる移動
- 拡大・縮小
- 分類ごとの色分け
- 分類の説明表示
- 各分類に属する論文・手法の一覧表示
- 論文選択時の既存詳細パネルとの連携
- 樹形図から研究系譜図への移動
- ライト・ダークモード対応
- PC・スマートフォン対応

### 表示方針

- 初期表示では主要な研究領域を把握できる構成にする
- 詳細な分類と論文は段階的に展開する
- ノードやラベルの重なりを防ぐ
- 分野横断的な研究は複数所属を明示する
- 樹形図の線は分類上の親子関係のみを表す
- 技術的な発展関係は既存の研究系譜図で表現する

必要に応じてD3.jsの階層レイアウトを利用する．

## 5．既存機能との連携

研究系譜図，パターン表，論文比較機能との整合性を維持する．

- 分類を選択すると，所属する論文を一覧表示する
- 論文を選択すると，既存の詳細パネルを表示する
- 選択した論文を研究系譜図で表示できる
- 既存の研究分野フィルタとの対応関係を維持する
- 複数分類に所属する論文を重複した別論文として扱わない

既存の検索機能を樹形図でも利用できるようにすることが望ましい．

## AIエディタによる解釈（作業開始時に追記）

- **タスクの種類**：分類体系の設計（文書），データの追加，Webサイトの機能追加，テスト，文書の作成である．`documentation.md` と既存の規約を適用する．
- **既存の構造との関係**：既存の7分野（`data/domains.json`）は研究系譜図の列・色・フィルタであり，変更しない．樹形図の分類は `data/research_taxonomy.json` に別に定義し，下位の分類は既存の分野のいずれか1つに対応付ける（対応する分野を持たない上位分類・横断的な分類を除く）．これにより分野フィルタとの対応を保つ．
- **所属の管理**：各論文ノードに所属する分類の ID の配列（`research_fields`）を追加する．論文情報は樹形図専用に複製しない．ノードの所属分類が対応する分野の集合は，ノードの `domains` と一致することを検証する．
- **親子関係**：各分類は `parent` と `children` を持ち，両者の整合と循環の無いことを検証する．樹形図の線は分類の親子関係と，分類への論文の所属のみを表す．
- **収録論文の無い分類**：既存のデータに所属する論文が無い分類は，order_004 で実在を確認した論文がある場合に限り設け，「収録 0 件」と明示する．
- **UI**：「研究分野樹形図」の表示モードを追加し，D3.js の木構造の配置（`d3.tree`）で描く．初期は上位2階層を表示し，下位の分類と論文は展開で表示する．
- **実施しないこと**：論文の追加，commit・push・デプロイ．
