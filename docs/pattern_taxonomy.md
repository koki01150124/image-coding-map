# 改良パターン・採用技術の分類体系

本文書は，Image Coding Map のパターン表で用いる分類体系の設計を記録する．分類の定義そのものは `data/patterns.json` で管理し，各ノードへの付与は `data/nodes/<id>.json` の `patterns` に記録する．

## 1. 分析した既存データ

既存44ノード（論文35件，標準規格の解説論文4件，ソフトウェア1件，構成例3件，未公開研究1件）について，検証済みの記述（`contributions`，`training`，`source_representation`，`strengths`）と，確認済みの系譜の関係（`derived_from` 15本，`builds_on` 15本）を確認した．
各ノードの主要な貢献は，(1) 既存方式のどこを変えたか（例: エントロピーモデルの構造，復号の並列化，SNR への適応）と，(2) 方式が何で構成されるか（例: ハイパープライア，拡散モデル，LDPC 符号）の2種類の記述からなる．前者は先行方式との差分であり，後者は部品である．例えば NTSCC は「ハイパープライア」を部品として用い（採用技術），その結果として「JSCC へのエントロピーモデルの導入」と「適応レート伝送」という改良を行っている（改良パターン）．両者を同じ軸にすると，部品を使っただけの論文が改良を行ったように見えるため，別の軸とした．

## 2. 検討した分類案

| 案 | 行の切り方 | 利点 | 問題 | 判断 |
| :--- | :--- | :--- | :--- | :--- |
| A. 構成要素の層による単一の軸 | 変換・量子化・エントロピーモデル・通信路・復号器の層 | 構成が明確 | 改良（何を良くしたか）と部品（何を使ったか）が混ざる．「SNR への適応」「誤り耐性」のような課題が層に収まらない | 不採用 |
| B. 目的（課題）による単一の軸 | レート，歪み，知覚品質，頑健性，計算量，適応性 | 研究の動機が分かる | 1つの論文が多くの目的に該当し，行の違いが手段を表さない．「レートの改善」がほぼ全ての LIC に該当して区別できない | 不採用 |
| C. 改良パターン（手段と課題の組）と採用技術（部品）の2軸 | 改良: 「エントロピーモデルの高精度化」「通信路条件への適応」など，先行方式に対する変更の種類．技術: 「ハイパープライア」「拡散モデル」など | 改良と部品を区別でき，order_005 の2種類の表に対応する．各行を論文の記述で判断できる | 判断基準を明文化する必要がある | **採用** |
| D. 参考リポジトリの改良パターン（最適化手法向け）の流用 | 慣性項，適応的スケーリング等 | 実装例がある | 対象分野が異なり，画像符号化・通信の改良に対応しない | 不採用 |

列は既存の7分野（生成・拡散型，LIC，従来型，SSCC，通信路符号化・関連技術，デジタル型 DeepJSCC，アナログ型 DeepJSCC）をそのまま用いる．分野はマップの列・色・フィルタと共通であり，変更すると既存の表示との対応が崩れるためである．

## 3. 採用した分類

### 3.1 改良パターン（13種）

改良パターンは「先行方式に対して何を改良したか」を表す．付与の根拠は，ノードの検証済みの主要な貢献と，確認済みの改良関係である．改良元が `derived_from`・`builds_on` で確認できる場合は `from` に記録する．

| ID | 表示名 | 定義の要点 | 判断基準の要点 |
| :--- | :--- | :--- | :--- |
| `learned_transform_coding` | 変換符号化の学習化 | 手設計の変換符号化を，学習した変換と量子化の近似による一括最適化に置き換える | 変換符号化の全体を学習可能にする方法を提案している |
| `entropy_model` | エントロピーモデルの高精度化 | 潜在表現の確率モデルを正確にして符号長を減らす | 確率モデルの構造（ハイパープライア，コンテキスト，混合分布）の変更が主要な貢献 |
| `transform_architecture` | 変換・骨格の構造の改良 | 符号化器・復号器のネットワーク構造の改良 | 注意機構・Transformer・混合ブロック等の骨格の変更 |
| `complexity_reduction` | 計算量・逐次処理の削減 | 計算量・逐次処理・反復回数を減らす | 並列化・ステップ数の削減等による速度の改善を主要な結果として示す |
| `perceptual_generative` | 生成モデルによる知覚品質の向上 | 生成モデルを復号に用いて知覚品質を改善する | 生成モデルを用い，知覚品質の改善を主張する |
| `rate_adaptation` | レートの可変化・配分 | 1つのモデルでの可変レート，情報源・通信路のレートの配分 | 可変レート・適応レート・目標品質の指定・レート配分が主要な貢献 |
| `progressive_feedback` | 漸進的伝送・フィードバックの利用 | 漸進的・階層的な伝送，フィードバックの利用 | 漸進的な符号，逐次改良，スケーラビリティ，フィードバック |
| `joint_channel_learning` | 通信路を含む共同学習への置き換え | 分離設計（または通信路を考慮しない学習）を，通信路を含む共同学習に置き換える | 通信路を学習に含める枠組みそのものの提案（DeepJSCC の部分的な改良は含めない） |
| `channel_adaptation` | 通信路条件への適応 | SNR・通信路・変調の変化への適応 | 異なる通信路条件への適応，通信路に合わせた変調・電力・レートの選択 |
| `digital_constraint` | 離散的な通信路入力への対応 | アナログ型 JSCC を，デジタル通信と互換な入力に置き換える | アナログ型の非互換性を課題とし，有限の入力・デジタルの符号化を提案 |
| `error_robustness` | 誤りへの頑健性の強化 | ビット誤り・通信路誤りによる劣化を抑える | 頑健性・誤り耐性の改善が主要な貢献 |
| `code_construction` | 通信路符号の構成・復号の改良 | 誤り訂正符号の構成・復号法・性能解析の改良 | 符号の族・構成法・復号アルゴリズム・解析が主要な貢献 |
| `coding_tool_extension` | 手設計の符号化ツールの拡張 | 規格の改訂による符号化ツールの追加・拡張 | 先行規格に対するツールの拡張とビットレートの削減 |

### 3.2 採用技術（16種）

採用技術は「方式を構成する技術要素」を表し，その論文が新しく提案したかを問わない．付与の根拠は，情報源表現・学習方法・主要な貢献の記述である．

| ID | 表示名 | 非該当の条件 |
| :--- | :--- | :--- |
| `handcrafted_transform` | 手設計の変換・予測 | なし |
| `learned_autoencoder` | 学習型の符号化器・復号器 | 学習を行わない方式（`training` が「学習なし」） |
| `attention_transformer` | 注意機構・Transformer | 同上 |
| `quantization_proxy` | 量子化・二値化の微分可能な近似 | 同上 |
| `hyperprior` | ハイパープライア（サイド情報） | 同上 |
| `context_model` | コンテキストモデル（自己回帰・チャネル方向） | 同上 |
| `variational_model` | 変分自己符号化器（VAE） | 同上 |
| `adversarial_training` | 敵対的学習 | 同上 |
| `diffusion_model` | 拡散モデル | 同上 |
| `pretrained_zero_shot` | 事前学習済みモデルのゼロショット利用 | 同上 |
| `codebook` | 符号帳・ベクトル量子化 | なし |
| `binary_latent` | 二値の潜在符号の直接伝送 | 学習を行わない方式 |
| `channel_in_training` | 通信路のモデルを含む学習 | `joint_channel_training` が `false` |
| `digital_modulation` | デジタル変調・信号点 | `transmission` が `analog` または `not_applicable` |
| `error_correcting_code` | 誤り訂正符号 | 同上 |
| `probabilistic_decoding` | 確率的・逐次的な通信路復号 | 同上 |

非該当の条件は，検証済みのフィールドから論理的に導けるものに限った．例えば「手設計の変換」には条件を設けていない．学習型のコーデックが手設計の変換を一部に含まないことは，記述から確認できないためである．

## 4. 判定の状態（未判定と非該当の区別）

ノードとパターンの組の状態は，該当・非該当・未判定の3値である（`tools/patterns.py`，`site/assets/patterns.js`）．

| 状態 | 条件 |
| :--- | :--- |
| 該当 | ノードの `patterns.<軸>.items` に根拠つきで挙げられている |
| 非該当 | 軸の判定が `assessed`（判定済み）で挙げられていない，軸が `not_applicable`（対象外），またはパターン定義の非該当の条件に一致する |
| 未判定 | 上記以外（`partial`（部分判定）で挙げられていない，または `unassessed`） |

軸の判定の状態は以下の方針で付けた．

- **改良パターン**：本文の該当箇所を照合したノード（31件）は `assessed` とした．確認した主要な貢献に含まれない改良は非該当とする．要旨のみのノード（6件）は `partial`，JPEG は先行方式との比較を確認していないため `unassessed` とした．Shannon 1948（理論），DDPM（生成モデルの基礎研究），BPG（既存規格の静止画像への適用），構成例3件は `not_applicable` とした．
- **採用技術**：構成要素を網羅的に確認したノードは無いため，Shannon 1948（対象外）を除く43件を `partial` とした．採用技術の非該当は，定義の非該当の条件から導けるものに限る．

### 5.2 重複の点検

意味の近い行の組について，区別の基準を以下のように定めた．

- **エントロピーモデルの高精度化と計算量の削減**：Channel-wise AR と ELIC は両方に該当する．前者は確率モデルの構造の変更，後者は逐次処理の削減という異なる貢献を記述しているためであり，重複ではない．Checkerboard は性能をほぼ同等に保った並列化のため，計算量の削減のみとした．
- **レートの可変化と通信路条件への適応**：レートの配分そのものと，通信路条件への追従を区別する．SwinJSCC と D²-JSCC は両方の記述があるため両方に該当する．
- **改良「通信路を含む共同学習への置き換え」と技術「通信路のモデルを含む学習」**：前者は分離設計を置き換える枠組みの提案（DeepJSCC，NECST，O'Shea，BFR-CAE），後者は部品として通信路のモデルを学習に含める全ての方式（14件）である．DeepJSCC-f のように後者のみに該当する論文があり，改良と採用技術を混同しないための区別である．
- **改良「生成モデルによる知覚品質の向上」と技術「拡散モデル」「敵対的学習」**：前者は知覚品質の改善を主張する論文，後者は部品として生成モデルを用いる方式である．Robust Turbo-DDCM は拡散モデルを用いるが，改良は誤りへの頑健性であり，知覚品質の向上には該当させていない．

### 5.3 欠落と偏り

- 「マルチユーザ」「セキュリティ」「OFDM・MIMO」などの改良は，既存のノードに該当例が無いため行を設けていない．order_004 の監査で追加推奨とした論文（OFDM-Guided DeepJSCC，DeepJSCC-MIMO 等）を収録する場合は，「通信路条件への適応」で表せるかを確認し，表せない場合に行を追加する．
- パケット損失耐性は「誤りへの頑健性の強化」で表せるが，ビット誤りとパケット損失を区別する必要が生じた場合は行を分ける．
- 従来型画像圧縮の列は，論文（`kind: paper`）が無いため，初期状態（論文のみ）では全て0件となる．標準規格を集計対象に含めると，HEVC・VVC（符号化ツールの拡張）と JPEG 2000 が計上される．

## 6. 拡張の手順

1. 新しいノードを追加する場合は，`patterns.improvements` と `patterns.techniques` に，判定の状態と，根拠（`kind`: `node_field`，`relation`，`abstract`，`full_text` 等，`detail`: 該当箇所）つきの項目を記入する．改良元が系譜の関係にある場合は `from` に記入する．
2. 既存の行で表せない改良・技術が複数の論文に現れた場合に，`data/patterns.json` に行を追加する．ID，表示名，定義，判断基準，表示の順，必要なら非該当の条件を記入する．1件だけのために行を増やさない．
3. `python tools/validate_data.py` で，未定義・重複の ID，対象外の軸の項目，改良元，非該当の条件との矛盾を検査する．描画コードの変更は不要である．
