# order_009：研究分野樹形図の縦・横レイアウト切り替え機能の実装

## 目的

`image-coding-map`の研究分野樹形図について，縦方向（上から下）を初期表示とし，横方向（左から右）に切り替えられる機能を実装する．

既存の樹形図の分類構造，論文情報，主要機能は維持すること．

## 1．既存実装の確認

最初に，研究分野樹形図のレイアウト計算，描画処理，ズーム・パン，ノード展開・折りたたみ，状態管理の実装を確認する．

既存の横方向レイアウトを可能な限り再利用し，縦方向と横方向で描画処理が重複しない設計とすること．

## 2．レイアウト切り替え

以下の2種類を実装する．

- **縦方向（初期表示）**：上位分類を上，下位分類を下に配置する．
- **横方向**：上位分類を左，下位分類を右に配置する．

樹形図の画面内に「縦方向」「横方向」の切り替えUIを設置する．

### 要件

1. 初期表示は縦方向とする．
2. ユーザーが任意のタイミングで表示方向を切り替えられるようにする．
3. 切り替え時にページ全体を再読み込みしない．
4. 切り替え前のノードの展開・折りたたみ状態を維持する．
5. 選択中の分類・論文を維持する．
6. 方向切り替え後は，表示内容が適切に収まるように位置と倍率を調整する．
7. 両方向で既存のズーム・パン操作を利用できるようにする．

ブラウザを再読み込みした場合は，原則として縦方向に戻る仕様とする．ただし，既存のURLパラメータなどで表示方向を指定する機能がある場合は，その設計との整合性を維持すること．

## 3．レイアウトの設計

### 縦方向

- 上位分類から下位分類へ，上から下に展開する．
- 同じ階層のノードを横方向に配置する．
- 親子関係を接続線で表す．
- 兄弟ノードやサブツリーの重なりを防ぐ．
- ノード数が多い場合は，十分な横幅を確保し，ズーム・パンで閲覧できるようにする．

### 横方向

- 現在の左から右への階層構造を維持する．
- 同じ階層のノードを縦方向に配置する．
- 既存の横方向表示と同等の操作性を確保する．

### 共通要件

- ノードやラベルの重なりを防止する．
- 分類名の長さを考慮して配置する．
- 接続線は分類上の親子関係のみを表す．
- 複数分野への所属や分類に関する既存の注記を維持する．
- ノード数や階層数が増えても，極端に表示が崩れない構造にする．
- ライトモード・ダークモードの両方で視認性を確保する．

D3.jsの既存実装を活用し，座標変換やリンク描画を方向に応じて切り替える方式を優先すること．

## 4．UI

樹形図の操作メニューに，以下の切り替えを追加する．

`表示方向：［縦方向｜横方向］`

- 現在の選択状態が明確に分かるデザインにする．
- 既存のサイトデザインに合わせる．
- PC・スマートフォンの両方で操作できるようにする．
- キーボード操作にも対応する．
- 他の表示モードには不要な操作UIを表示しない．

## 5．既存機能との互換性

以下の機能を維持すること．

- 分類ノードの展開・折りたたみ
- 分類と論文の選択
- 論文詳細パネル
- 論文検索
- 研究系譜図への移動
- ズーム・パン
- 全体表示
- 研究分野ごとの色分け
- ライト・ダークモード
- GitHub Pagesでの動作

研究系譜図やパターン表など，樹形図以外の画面のレイアウトは変更しないこと．

## 6．検証

既存テストに加えて，以下を確認する．

1. 樹形図の初期表示が縦方向である．
2. 縦方向では親ノードより子ノードが下に配置される．
3. 横方向では親ノードより子ノードが右に配置される．
4. 縦方向から横方向，横方向から縦方向へ正常に切り替えられる．
5. 切り替え後も展開・折りたたみ状態が維持される．
6. 選択中の分類・論文が維持される．
7. ノードやラベルの不適切な重なりがない．
8. 両方向でズーム・パン・全体表示が機能する．
9. PC・スマートフォンの表示幅で操作できる．
10. ライト・ダークモードで表示が破綻しない．
11. 既存の研究系譜図・パターン表・論文比較機能が正常に動作する．
12. GitHub Pagesの`/image-coding-map/`で正常に表示される．

Playwrightなどの既存のブラウザテストを使用し，可能であれば両方向のスクリーンショットを保存すること．
